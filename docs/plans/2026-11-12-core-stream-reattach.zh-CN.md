# Core 原生流多观察重附修复计划

日期：2026-11-12。关联 OAI #152、DSH #12；依赖大会话修复 PR149 / DSH PR11。

## 已确认问题

真实 Core 将宿主读取与客户端 SSE 观察分开：客户端断开后，后台生产者继续消费原任务并提交真实回执。两侧桥却把会话 Busy 绑定到第一条宿主观察，导致原任务仍运行且身份已确认时，相同 clientMessageId 的第二条观察被 SESSION_BUSY 拒绝。真实模型只提交一条输入即发现失败；零模型真实 Core HTTP 和原样桥处理器已复现。

## 修复约束

- 保留 Core 独立生产者和宿主任务；断观察不能取消宿主或自动重投。
- 分开单次提交的互斥身份和各观察的清理所有权。同一已接纳身份可独立重附原 generation；并发首次受理、迟到回执和未知事实不得再 prompt。
- 不同身份保持明确的队列与 Busy / 未知边界，不能被别的观察结束误放行或跨代次串线。
- 各观察继续使用既有有界队列、写出背压、期限、独立 AbortSignal 和 finally 清理；慢观察或其中一个断开不影响另一个观察。
- 只使用最小身份与受理事实作为共享状态，不保存 HTTP 响应、正文或长期监听器；不宣称跨重启幂等或精确一次。

## 实施与验收

先新增同身份双观察和受理挂起的失败回归，再同步两侧实现。覆盖多个观察交错关闭、不同输入隔离、终态重放、未知不重投、慢消费者和监听器清理。保留现有 133 / 90 项 Node、102 项 Core、类型和漂移检查。

使用零模型真实 Core HTTP 反馈环验证客户端断开后第二观察收到原 generation 的增量与终态，原生 promptCount 仍为一。独立审查及完整真实模型、正式服务、模拟器验收由主任务统一完成；本分支不部署、不操作私人会话。

当前状态：两侧源码与受控反馈环已完成，原生真实模型和部署/模拟器由主任务继续；详见 `../reviews/2026-11-12-core-stream-reattach.zh-CN.md`。
