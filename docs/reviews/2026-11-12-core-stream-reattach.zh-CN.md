# Core 原生流同身份多观察修复证据

日期：2026-11-12，关联 OAI #152、DSH #12。

## 已完成的实现

每个会话的提交记录与每条观察槽分别管理。相同 clientMessageId、且宿主具备权威生成恢复时，可共用原提交并各自查询、附着原 generation；只读预查之后，仍活跃观察通过同步检查 submitted=false 才能领取首次 prompt；首观察尚未提交即离开时允许交接，已提交/未知绝不交接重投。无客户端身份或缺少权威恢复的旧宿主保留原有 Busy 行为。

每条观察只清理自己的回执槽、事件监听、流队列和 follow；共享提交记录通过对象身份比较释放，旧观察结束不能移除后续记录。全部观察已经离开时，未解决受理只保留会话 ID、客户端 ID、提交状态和空观察集合，不保留正文、HTTP 或监听器；后续同身份不能重投，不同身份返回明确 OUTCOME_UNKNOWN。迟到 accepted:false、或权威客户端生成查询、原生用户事实恢复后清理记录。没有事实时不伪造空闲，不宣称跨重启精确一次。

实时错误与未知终态现携带已经证实的原生 userMessageId、generationId 及真正存在时的 reply messageId；没有助手消息时不补造回复 ID。

## 红绿与受控反馈环

新增首批 6 项回归在旧实现为 5 失败、1 通过，明确捕获 SESSION_BUSY 和同身份重复 prompt。后续补齐无响应事实、迟到未知/拒绝、旧观察交错释放、慢观察溢出、错误身份和已关闭观察，共 14 项。

双侧完整 Node 套件、Core DSH 契约、类型及 11 对源码/测试漂移结果见本目录原始脱敏输出。保留基线失败，未修改旧日志冒充通过。

`core-http-reattach-probe.py` 启动真实 create_core/create_app、真实 HMAC 注册和 HTTP/SSE，与原样桥处理器互通。宿主事件使用受控夹具、模型请求为 0，不是 DSH/模型端到端证据。两侧结果均为：首次 SSE 客户端断开后宿主仍 running、promptCount=1、2 个监听；第二观察成功收到同 generation、delta、done，观察期间 4 个监听，真实格式终态后监听为 0，promptCount 仍为 1。Core 旧观察 socket 的 ClientConnectionResetError 保留，未把它当宿主失败或取消任务。

## 验证边界

独立审查、真实模型 Core HTTP/SSE、正式本机与 Android 模拟器由主任务继续；此分支不部署、不调用模型、不读取私人会话/凭据。未决提交记录是进程内的最小安全屏障，真正永久缺失的宿主事实不会被超时自动清除；跨重启依赖原生持久记录，不宣称恰好一次。


## 独立审查后竞态收敛

首观察创建记录但尚在只读预查时断开，旧初修把提交权固定在该观察，导致仍活跃观察返回未知而没有真正提交。新增第 14 项先确认红，再将提交权改为共享记录中同步检查和设置 submitted，确保仍未提交才可交接且只领取一次。

另补迟到传输拒绝不得抢在新观察的权威读取之前结束：共享结果先记在最小记录中，待该观察预查完成，无权威事实才应用未知回执。有效原生用户事件立即标记权威事实，终态后 Agent 卸载也不会残留未知屏障。对应回归覆盖冷读取、预查窗口和退出后的后续新输入。

最终两侧完整 Node 为内置 147、独立 104，通过；Core DSH 全组 102 已通过，最小竞态增量后跨语言 6 项再次通过；类型及 11 对漂移一致。此前 Fast/PR 均退出 0，其中 PATH 未带 DSH 的该轮明确 139 通过、5 真实宿主可选项跳过，不冒称真实宿主层已在门禁中执行；完整 Node 单独运行含真实宿主层全通过。
