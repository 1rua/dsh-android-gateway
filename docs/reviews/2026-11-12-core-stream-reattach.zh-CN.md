# Core 原生流同身份多观察修复证据

日期：2026-11-12，关联 OAI #152、DSH #12。

## 已完成的实现

每个会话的提交记录与每条观察槽分别管理。相同 clientMessageId、且宿主具备权威生成恢复时，可共用原提交并各自查询、附着原 generation；只读预查之后，仍活跃观察通过同步检查 submitted=false 才能领取首次 prompt；首观察尚未提交即离开时允许交接，已提交/未知绝不交接重投。无客户端身份或缺少权威恢复的旧宿主保留原有 Busy 行为。

每条观察只清理自己的回执槽、事件监听、流队列和 follow；共享提交记录通过对象身份比较释放，旧观察结束不能移除后续记录。全部观察已经离开时，未解决受理只保留会话 ID、客户端 ID、提交状态和空观察集合，不保留正文、HTTP 或监听器；后续同身份不能重投，不同身份返回明确 OUTCOME_UNKNOWN。迟到 accepted:false、或权威客户端生成查询、原生用户事实恢复后清理记录。没有事实时不伪造空闲，不宣称跨重启精确一次。

实时错误与未知终态现携带已经证实的原生 userMessageId、generationId 及真正存在时的 reply messageId；没有助手消息时不补造回复 ID。

## 独立审查后竞态收敛

首观察创建记录但尚在只读预查时断开，旧初修把提交权固定在该观察，导致仍活跃观察返回未知而没有真正提交。新增第 14 项先确认红，再将提交权改为共享记录中同步检查和设置 submitted，确保仍未提交才可交接且只领取一次。

另补迟到传输拒绝不得抢在新观察的权威读取之前结束：共享结果先记在最小记录中，待该观察预查完成，无权威事实才应用未知回执。有效原生用户事件立即标记权威事实，终态后 Agent 卸载也不会残留未知屏障。对应回归覆盖冷读取、预查窗口和退出后的后续新输入。
